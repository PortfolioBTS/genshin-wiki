# Genshin Wiki — переработка проекта

Дата: 2026-10-25
Статус: согласовано в чате, ждёт ревью спецификации

## Цель

Проект для портфолио. Работодатель, который откроет сайт или репозиторий, должен увидеть:

- аккуратный, современный код со сборкой, тестами, линтером и CI;
- верные и свежие данные (сейчас многие факты выдуманы, а версия игры устарела на 1,5 года);
- приятный и удобный интерфейс, в том числе на телефоне;
- честность: демо-функции подписаны как демо.

## Исходное состояние (что не так)

- 8 статических HTML-страниц, шапка и подвал скопированы в каждую.
- `data.js` вручную набран и содержит несуществующих персонажей («Чэнь Хуэй», «Юй Пу», «Каминаре» и др.), неверные факты (архонт Натлана «Пирамус», Далия 5★), «101 персонаж» при ~80 записях, версию 5.7 вместо текущей 7.1.
- Аккаунты живут только в localStorage браузера посетителя; пароль «хешируется» через base64; код подтверждения виден в DevTools.
- Форма «предложить правку» скопирована в 5 файлов; `showToast`, `getUser` продублированы.
- Пользовательские и прочие строки вставляются через `innerHTML` без экранирования.
- `README.md` и `SETUP.md` идентичны и описывают только настройку EmailJS; в них открыто лежит личный email.

## Принятые решения

| Вопрос | Решение |
|---|---|
| Стек | Vite + ванильный JavaScript (ES-модули) |
| Архитектура | Многостраничный сайт (MPA), общие куски подставляются при сборке |
| Источник данных | npm-пакет `genshin-db` (официальная русская локализация из игры), генерация JSON скриптом |
| Аккаунты | Остаются демо (localStorage), но честно подписаны и с настоящим хешированием |
| Хостинг | GitHub Pages через GitHub Actions |

## 1. Структура и сборка

```
genshin-wiki/
├── index.html, characters.html, character.html, weapons.html, artifacts.html,
│   regions.html, guides.html, patches.html, banners.html, auth.html
├── partials/
│   ├── header.html
│   └── footer.html
├── src/
│   ├── pages/        по модулю на каждую HTML-страницу
│   ├── components/   карточки, панель фильтров, форма предложения, тост, поиск, изображение с фолбэком
│   ├── lib/          auth, storage, filters, url-state, escape-html, emailjs, format
│   ├── data/
│   │   ├── generated/    JSON, созданные скриптом (коммитятся в репозиторий)
│   │   └── content/      тексты, написанные вручную (регионы, гайды, патчи, баннеры)
│   └── styles/       base.css, layout.css, components.css, pages/*.css
├── scripts/data/
│   ├── package.json  отдельный, только с genshin-db (179 МБ не попадают в основной npm install)
│   └── build-data.mjs
├── tests/
├── vite.config.js
├── .env.example
└── .github/workflows/
    ├── ci.yml        lint + test + build на push и pull request
    └── deploy.yml    сборка и публикация на GitHub Pages при push в main
```

**Подстановка partials.** Небольшой плагин Vite в `transformIndexHtml` заменяет `<!-- include:header -->` и `<!-- include:footer -->` содержимым файлов из `partials/` и ставит `class="active"` и `aria-current="page"` на пункт меню текущей страницы. Результат статический, без мигания при загрузке.

**Vite.** `build.rollupOptions.input` перечисляет все HTML-страницы. `base: './'`, чтобы сайт работал по любому пути, включая `https://<owner>.github.io/genshin-wiki/`.

**Экранирование.** `escapeHtml()` в `src/lib/escape-html.js`. Любая строка, попадающая в шаблон для `innerHTML`, проходит через неё. Исключение — заранее очищенная разметка описаний из скрипта данных (см. раздел 2), она помечается явно.

**EmailJS.** Пакет `@emailjs/browser` из npm. Ключи берутся из `import.meta.env.VITE_EMAILJS_PUBLIC_KEY`, `VITE_EMAILJS_SERVICE_ID`, `VITE_EMAILJS_TEMPLATE_VERIFY`, `VITE_EMAILJS_TEMPLATE_PROPOSAL`. Локально они лежат в `.env` (в git не попадает, есть `.env.example`), при деплое приходят из GitHub Actions Variables. Если ключей нет, включается демо-режим. Адрес администратора задаётся только в шаблоне EmailJS и из репозитория убирается.

**Документация.** `SETUP.md` удаляется. `README.md` переписывается: описание, скриншот, стек, структура, команды (`dev`, `build`, `test`, `lint`, `data:update`), включение GitHub Pages, необязательная настройка EmailJS, источники данных, дисклеймер про HoYoverse.

## 2. Данные

### Генерация (`npm run data:update`)

Скрипт `scripts/data/build-data.mjs` с зафиксированной версией `genshin-db` (сейчас 5.2.14) и языком `Russian` создаёт:

- `characters.json` — лёгкий список для каталога и главной: `id`, `slug` (из английского имени, например `skirk`), `name`, `title`, `rarity`, `element`, `weapon`, `region`, `birthday`, `constellation`, `version`, `icon` (имя файла иконки).
  - Регион выводится из `associationType` (`ASSOC_MONDSTADT` → «Мондштадт», `ASSOC_NODKRAI` → «Нод-Край» и т. д.). Необычные значения (`ASSOC_FATUI`, `ASSOC_OMNI_SCOURGE`, `ASSOC_RANGER` и др.) сопоставляются явной таблицей. Если значение не сопоставлено, скрипт падает, чтобы новые значения не терялись молча.
  - Путешественник (Итэр и Люмин) — одна запись без стихии. «Манекены» исключаются.
- `characters/<slug>.json` — подробности для страницы персонажа: описание, таланты (3 боевых и пассивки), созвездия C1–C6, суммарные материалы возвышения персонажа.
- `weapons.json` — оружие 3–5★: `slug`, `name`, `type`, `rarity`, базовая атака и доп. стат на 90 уровне, название пассивки и её текст на R1, `icon`, `version`.
- `artifacts.json` — сеты с максимальной редкостью 4–5★: `slug`, `name`, бонусы 2 и 4 предметов, `icon` (цветок), `version`.
- `search-index.json` — `{ type, slug, name, icon }` для всех записей выше, для глобального поиска.

Очистка текста: теги игры `<color=#…>…</color>` превращаются в `<span class="hl">…</span>`, остальные теги удаляются, текст внутри экранируется. Так получается доверенная разметка, которую можно вставлять как есть.

Выход скрипта детерминирован (стабильная сортировка), чтобы диффы при обновлении были читаемыми.

### Ручной контент (`src/data/content/`)

Перед написанием сверяется с источниками в интернете. Внизу страниц выводится «Данные актуальны на 25.10.2026».

- `regions.js` — нации Тейвата и Нод-Край: верные архонты и стихии, короткие описания.
- `patches.js` — версии 6.0–7.1 с датами выхода и главными изменениями. Новые персонажи и оружие версии подставляются автоматически по полю `version` из сгенерированных данных.
- `banners.js` — текущая фаза 7.1 (реран Скирк и Эскофье, 13.10–03.11.2026) и анонс 7.2 (Митя и Валерий, с 04.11.2026). Выдуманные «события» удаляются.
- `guides.js` — короткие карточки гайдов, устаревшие факты исправлены (например, добавлен Воображариум).

### Вне рамок

- Роли «DPS / саппорт» убираются: их нет в данных, а вручную это субъективно.
- Цифры на главной («101 персонаж» и т. п.) не хардкодятся, а считаются из данных.

## 3. Страницы и интерфейс

Сохраняется текущий тёмный стиль с цветами стихий.

- **Общее.**
  - Шапка с меню-бургером на узких экранах и глобальным поиском.
  - Поиск загружает `search-index.json` при первом фокусе. Выпадающий список сгруппирован по типам, управляется с клавиатуры (↑ ↓ Enter Esc). Персонаж открывается на `character.html?id=<slug>`, оружие на `weapons.html?q=<имя>`, артефакт на `artifacts.html?q=<имя>`.
- **Изображения.** Компонент `<img loading="lazy">` с цепочкой источников: официальная ссылка HoYoLAB из `genshin-db`, затем `enka.network/ui/<icon>.png`, затем заглушка (кружок цвета стихии с первой буквой). Обязательный `alt`.
- **Персонажи.**
  - Фильтры: стихия, редкость, оружие, регион. Поиск и сортировка по имени или по версии (новые первыми).
  - Состояние фильтров хранится в URL (`?el=cryo&rarity=5&weapon=sword`), поэтому ссылки с главной (`?el=pyro`) продолжают работать.
  - Переключатель «карточки / таблица» заменяет дублирующую таблицу; выбор вида запоминается в localStorage.
- **Страница персонажа** (`character.html?id=<slug>`):
  - Шапка с портретом, стихией, оружием, редкостью, регионом, днём рождения и созвездием; описание.
  - Таланты во вкладках, созвездия C1–C6, материалы возвышения.
  - Если ID неизвестен, понятная заглушка со ссылкой на каталог.
- **Оружие и артефакты.** Иконки, фильтры (тип и редкость; для артефактов — редкость), поиск через `?q=`, переключатель вида.
- **Главная.** Счётчики из данных и блок «Новое в версии 7.1», собранный автоматически.
- **Патчноуты.** По каждой версии — новые персонажи со ссылками на их страницы.
- **Доступность.**
  - Обработчики событий навешиваются в JS, атрибутов `onclick` в HTML нет.
  - `aria-pressed` у кнопок фильтров, видимый `:focus-visible`, семантичные `<button>` и `<nav>`.
- **Форма «предложить правку».** Один компонент вместо пяти копий; страница передаёт свой список категорий.

## 4. Аккаунты (честное демо)

- На `auth.html` и в форме предложения заметная плашка: «Демо: аккаунты и предложения хранятся только в этом браузере».
- Пароли хешируются через PBKDF2-SHA-256 (Web Crypto, 600 000 итераций по рекомендации OWASP, случайная 16-байтная соль на пользователя). Хеш и соль хранятся в hex.
- Миграция старого формата: при входе пользователь без соли проверяется по старой схеме (base64), и при успехе пароль сразу перехешируется в новом формате.
- Коды подтверждения и сброса — 6 цифр через `crypto.getRandomValues`, срок жизни 10 минут. Если EmailJS настроен, код отправляется письмом, иначе показывается на экране.
- Предложения хранятся в localStorage и видны в профиле. Если EmailJS настроен, они дополнительно отправляются письмом.
- Код делится на `src/lib/auth.js` (чистая логика: валидация, хеширование, хранилище пользователей, коды; покрывается тестами) и `src/pages/auth.js` (интерфейс).
- Ключи localStorage (`gw_user`, `gw_users`, `gw_proposals`) сохраняются, чтобы не терять существующие демо-данные.

## 5. Качество

- **ESLint** (flat config) и **Prettier**; скрипты `lint` и `format`.
- **Vitest** (окружение jsdom там, где нужен DOM). Покрываются:
  - фильтрация и сортировка, чтение и запись состояния URL;
  - `escapeHtml` и очистка игровой разметки;
  - auth: хеширование, проверка, миграция, валидация, коды;
  - сопоставление регионов и трансформации в скрипте данных;
  - плагин partials (подстановка и активный пункт меню).
- **CI** (`ci.yml`): `npm ci`, `lint`, `test`, `build`.
- **Деплой** (`deploy.yml`): сборка с переменными EmailJS из Actions Variables и публикация через `actions/deploy-pages`. Владельцу репозитория нужно один раз включить Settings → Pages → Source: GitHub Actions.
- **Ручная проверка.** Собранный сайт открывается в headless Chromium (Playwright): нет ошибок в консоли, фильтры и поиск работают, страница персонажа рендерится.

## Порядок работ

1. **Фундамент.** Vite, структура, partials, перенос текущих страниц на модули без изменения поведения, экранирование, линтер, тесты, CI и деплой, новый README.
2. **Данные.** Скрипт генерации, ручной контент со сверкой, удаление `data.js`.
3. **Интерфейс.** Изображения, новые фильтры и URL-состояние, переключатель вида, страница персонажа, поиск, бургер-меню, главная и патчноуты из данных.
4. **Аккаунты.** Разделение auth, PBKDF2 с миграцией, демо-плашки, общий компонент формы.

После каждого этапа сайт собирается и работает; каждый этап — отдельные коммиты.

## Риски и ограничения

- **Изображения не проверить в среде разработки.** Хосты картинок (HoYoLAB, enka.network) закрыты сетевой политикой окружения, поэтому их загрузку нужно проверить в браузере после деплоя. Цепочка фолбэков гарантирует, что сломанной картинки не будет видно.
- **Внешние картинки.** Изображения принадлежат HoYoverse и подгружаются с внешних хостов. В README есть дисклеймер фан-проекта.
- **Устаревание.** Баннеры и патчи устаревают с каждой версией игры. Дата актуальности выводится на страницах, а `data:update` обновляет основную базу одной командой.
- **Качество перевода.** Названия берутся из официальной локализации игры через `genshin-db`. Отдельные строки пакета могут быть неточны; это принимается.
